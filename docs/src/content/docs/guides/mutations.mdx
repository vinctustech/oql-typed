title: Mutations

import { Tabs, TabItem, Aside } from '@astrojs/starlight/components'

Mutations are methods on every entity handle — `db.user.insert(...)`, `db.trip.delete(...)`. They carry the same type-safety guarantees as queries: the input shape is enforced, nullable fields are honored, and the returned row is fully typed.

## `db.<entity>.insert(input)`

The input is typed:

- Non-nullable columns with no default → **required**
- Nullable columns → **optional** (omit to insert `NULL`)
- `manyToOne` relations → accept the FK id directly
- Primary key is optional — OQL auto-generates if omitted; pass one explicitly to override

<Tabs syncKey="insert">
  <TabItem label="TypeScript">
    ```typescript
    const alice = await db.user.insert({
      id:        crypto.randomUUID(),
      email:     'alice@example.com',
      firstName: 'Alice',
      lastName:  'Adams',
      role:      'AUTHOR',
      enabled:   true,
      // rating, metadata, lastLoginAt omitted — all nullable
    })
    // => {
    //      id: string,
    //      email: string,
    //      firstName: string,
    //      lastName: string,
    //      role: 'ADMIN' | 'AUTHOR' | 'READER',
    //      enabled: boolean,
    //      rating: number | null,
    //      metadata: unknown | null,
    //      lastLoginAt: Date | null,
    //    }
    ```
  </TabItem>
  <TabItem label="With a manyToOne FK">
    ```typescript
    const draft = await db.post.insert({
      id:        crypto.randomUUID(),
      title:     'Hello',
      slug:      'hello',
      body:      '...',
      status:    'DRAFT',
      featured:  false,
      viewCount: 0,
      wordCount: 0n,
      createdAt: new Date(),
      keywords:  [],
      visitHistogram: [],
      author:    alice.id,   // ← FK id for the manyToOne
      // category, reviewedBy, publishedAt, publishedOn, publishTime,
      // editWindow, readingTime, metadata omitted — all nullable
    })
    ```
  </TabItem>
  <TabItem label="What the compiler rejects">
    ```typescript
    db.user.insert({
      id:    crypto.randomUUID(),
      email: 'bob@example.com',
      // ✗ missing required: firstName, lastName, role, enabled
    })
    // → Type error: missing required fields

    db.user.insert({
      id:        crypto.randomUUID(),
      email:     'bob@example.com',
      firstName: 'Bob',
      lastName:  'Brown',
      role:      'SUPERADMIN',   // ✗ not in UserRole
      enabled:   true,
    })
    // → Type error: 'SUPERADMIN' not assignable to 'ADMIN' | 'AUTHOR' | 'READER'
    ```
  </TabItem>
</Tabs>

## `db.<entity>.update(id, patch)`

Every field in the patch is optional. Returns the primary key plus the fields you patched, all typed.

<Tabs syncKey="update">
  <TabItem label="TypeScript">
    ```typescript
    const changed = await db.user.update(alice.id, {
      firstName: 'Alicia',
      role:      'ADMIN',
    })
    // => {
    //      id: string,
    //      firstName: string,
    //      role: 'ADMIN' | 'AUTHOR' | 'READER',
    //    }
    ```
  </TabItem>
  <TabItem label="Clearing a nullable field">
    ```typescript
    await db.post.update(postId, {
      publishedAt: null,    // explicitly clear to NULL
    })
    ```
  </TabItem>
</Tabs>

## `db.<entity>.delete(id)`

Removes a single row by primary key. Returns `Promise<void>` — there is no row echo.

```typescript
await db.user.delete(alice.id)
```

The id is typed as `string | number` (matching how primary keys are declared), so a mistyped id is a compile error.

## `db.<entity>.bulkDelete(ids)`

Removes many rows by primary key in one call. Returns `Promise<void>`.

```typescript
await db.tripStep.bulkDelete(removedStepIds)   // ids: (string | number)[]
```

<Aside type="tip">
Want to bulk-insert, bulk-update, or upsert? Mutations return typed single rows (or `void` for deletes). Compose them with your own transaction helper on the backend side (e.g. PostgreSQL `pg` transactions) — the mutation methods don't implicitly span a transaction.
</Aside>
